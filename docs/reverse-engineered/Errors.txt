Fault/alarm code tables per inverterType, re-derived from SolaXCloud 7.7.1 (`invAdres.getErrorData(inverterType)`).

Source of the raw codes (confirmed in 7.7.1): the SAME local `ReadRealTimeData` response documented in
`Data1.txt`/`Data2.txt` carries a top-level `Error` object, sibling to `sn`/`ver`/`type`/`Data`/`Information`:

```json
{
  "sn": "...",
  "type": 15,
  "Data": [...],
  "Information": [...],
  "Error": {
    "ErrorCode": "16,27",
    "ErrorCodeNew": "101_5,205_1"
  }
}
```

- `Error.ErrorCode` - legacy format, a comma-separated list of plain numeric codes (e.g. `"16,27"`). Each code is
  looked up directly in the flat `code: "message"` tables below via `getErrorData(inverterType)[code]`.
- `Error.ErrorCodeNew` - newer composite format, a comma-separated list of `MAIN_SUB` codes (e.g. `"101_5"` = main
  code `ERR101`, sub-code `5`). Used by inverterType `64, 67, 69, 108, 109, 111` (see the `ERR<main>` section at the
  bottom of this file) - though nothing stops any inverterType's dongle firmware from sending either field.
- Both fields are optional/absent when there's nothing to report (the app treats missing/empty `Error`,
  missing/empty `ErrorCode` and missing/empty `ErrorCodeNew` as "no active faults").
- Which of the two fields is present depends on the dongle/inverter firmware, not on `inverterType` alone - the app
  always checks `ErrorCode` first and only falls back to `ErrorCodeNew` if `ErrorCode` is absent/empty.

This is a query-time snapshot of *currently active* faults (there's a separate, unrelated `/historyalarm` screen in
the app for historical alarm logs, not covered here - that one is not fed from this local endpoint).

Format below mirrors `Data2.txt`/`Information.txt`: one block per group of inverterType codes that share an
identical table, `code: "message"`.

fed from `Error.ErrorCodeNew` as `"<main>_<sub>"` entries (e.g. `"101_5"` = `ERR101` sub-code `5`), covering 167
distinct main codes (`ERR101`..`ERR444`, not contiguous).

dynamically at runtime via i18n keys like `commErrormsg.main_101` / `commErrormsg.sub_101_5`, which aren't present in
