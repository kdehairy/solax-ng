Following functions are used below to interpret some values correctly:
function read8BitUnsigned(n) {
  return n % 256;
}

function read8BitHighUnsigned(n) {
  return Math.floor(n / 256);
}

function read8BitHighSigned(n) {
  const v = Math.floor(n / 256);
  return v < 128 ? v : v - 256;
}

function read16BitSigned(n) {
  if (n < 32768) {
    return n;
  } else {
    return n - 65536;
  }
}

function read32BitUnsigned(a, b) {
  return a + 65536 * b;
}

function read32BitSigned(a, b) {
  if (b < 32768) {
    return a + 65536 * b;
  } else {
    return a + 65536 * b - 4294967296;
  }
}

function hextobtye(n) {
  // Returns an array of 16 bits (each "0" or "1"); index 0 is the least significant bit.
  return n.toString(2).padStart(16, "0").split("").reverse();
}

Notes on some of the shared/aggregate fields seen on newer (G4/G5+, hybrid cluster, "big"/GrandHV/ForthPlus and
microinverter G3) inverter types above:
- BAT_Power1/BAT_Power2, BatteryCapacity1/2, BatteryVoltage1/2, BatteryTemperature1/2, Bthroughputs/Bthroughputs2:
  per-battery-pack readings on inverters that support two separate battery packs/BMS (BAT_Power itself is usually
  the sum of both packs).
  PowerDc3..PowerDc12/Vdc3..Vdc12/Idc3..Idc12: additional MPPT/PV string channels beyond the first two, present on
  inverters with more than two trackers (some hybrid G4/G5 variants, "big"/GrandHV/ForthPlus commercial inverters).
- CurrBranch1..CurrBranch30: individual PV string/branch currents on multi-MPPT commercial string inverters
  (GrandHV/ForthPlus/"big" families).
- GenPower/GenEnergy, solarInverterPower/solarInverterEnergy, TotalThirdDevicePower/TotalThirdDeviceYield: readings
  related to a generator input or a third-party/solar meter hooked up alongside the inverter (site with an extra
  meter or AC-coupled solar inverter).
- ParallelStatus/ParallelOnlineStatus/BATNumber: cluster/parallel installation status for inverters that can be
  wired together in a multi-unit installation.
- InverterConfigStatus: a bitfield (decoded with hextobtye) carrying various configuration/feature flags; at least
  bit 0 is used elsewhere in the app to detect "PV only" (no battery wired) configurations, and type 32 (X3 Hybrid
  G4 PLUS) uses bit 1 to pick between two different Yield_Today/Yield_Total register widths.
- Grid_L1L2_Voltage: direct line-to-line (or L1-L2) voltage reading on split-phase inverters, separate from
  GridAVoltage which on those same types is calculated as the sum of the two individual leg-to-neutral voltages.

See `Information.txt` for the derived-flag rules the official app applies on top of these fields per inverterType:
which types never have a battery or PV input, when GenPower/solarInverterPower/TotalThirdDevicePower are actually
meaningful, when `InverterConfigStatus` bit 0 overrides `hasBattery` for a specific installation, and the numeric
`RunMode` thresholds used to detect EPS/backup mode (it's not simply `RunMode == 7` for most of the types above).

See `Errors.txt` for per-inverterType fault/alarm code -> message tables. The codes come from the same
`ReadRealTimeData` response, but from a top-level `Error` object (`Error.ErrorCode`/`Error.ErrorCodeNew`) alongside
`Data`/`Information`, not from any offset inside the `Data[]` array documented above.
